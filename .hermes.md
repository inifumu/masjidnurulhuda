# Project Instructions — Masjid Nurul Huda

Dokumen ini adalah konteks utama untuk Hermes Agent saat bekerja di repository ini.
Gunakan Bahasa Indonesia untuk penjelasan, laporan perubahan, dan dokumentasi proyek.
Zona waktu bisnis: `Asia/Jakarta`.

## 1. Mandat Utama

1. Kerjakan permintaan pengguna saat ini sebagai tujuan utama.
2. Verifikasi dokumentasi terhadap source code, migration, konfigurasi, dan test aktual.
3. Gunakan perubahan sekecil mungkin yang menyelesaikan akar masalah secara lengkap.
4. Jangan mengorbankan keamanan, integritas transaksi kas, RBAC, atau kemampuan recovery demi kecepatan.
5. Jangan menyatakan pekerjaan selesai tanpa evidence yang benar-benar dijalankan.
6. Jangan membuat asumsi ketika fakta dapat ditemukan di repository. Jika tetap tidak ditemukan, tulis `Not found`.

## 2. Hierarki Sumber Kebenaran

Jika informasi bertentangan, gunakan urutan berikut:

1. Permintaan pengguna saat ini dan batasan eksplisitnya.
2. File `.hermes.md` ini untuk aturan proses, safety, dan quality gate.
3. Source code, migration yang berlaku, konfigurasi runtime, dan automated test sebagai fakta behavior operasional.
4. `SYSTEM_MAP.md` sebagai peta arsitektur dan flow aktual.
5. `RUNBOOK.md`, workflow CI/CD, dan konfigurasi deployment.
6. `ROADMAP.md` sebagai backlog aktif.
7. Dokumen dalam `docs/archive/` hanya sebagai histori, bukan instruksi aktif.

Untuk perubahan UI/UX, `DESIGN.md` adalah source of truth visual dan `docs/UI_UX_REDESIGN_AUDIT.md` adalah source audit/adoption/migration workstream. Source/test tetap lebih tinggi untuk behavior operasional.

`optimalisasi_plan.md` lama telah deprecated. Jangan menggunakannya sebagai gate, kontrak, atau urutan kerja aktif.

Aturan domain dalam dokumen ini terdiri dari dua kategori:

- **Invariant wajib untuk perubahan baru:** perubahan tidak boleh menambah hard-delete approved, bypass RBAC, race condition, atau kebocoran data baru.
- **Baseline terverifikasi:** audit/void transaksi, idempotency, shared contract, exact same-origin/security headers, persistent D1 login limiter failure-only (sukses mereset bucket), eliminasi known default credential melalui migration 0017 + provisioning lokal, serta account lifecycle/revocation/recovery guard memiliki evidence source/test dan wajib dipertahankan.
- **Baseline terverifikasi P0.5:** `Done`. Real-D1 concurrency/reject/role/ownership/period-summary, auth/Finance recovery, safe media deletion, cleanup fixture, migration 0016, independent review, authenticated Chromium E2E 360×800+1366×900, dan seluruh final gate memiliki evidence lokal.

## 3. Konteks Sistem

Stack utama:

- Frontend: Vue 3, TypeScript, Vue Router, Pinia, Tailwind CSS, shadcn-vue, lucide-vue-next.
- Backend: Hono.js pada Cloudflare Pages/Workers.
- Database: Cloudflare D1.
- Media: Cloudflare R2.
- Auth: JWT dalam cookie `httpOnly` dengan `token_version` untuk revocation.

Alur arsitektur utama:

```text
Vue View/Component
→ Composable/Store
→ Frontend Service + httpClient
→ Hono Route/Middleware
→ Domain Service/Policy
→ Repository/Query
→ D1 / R2 / External API
```

Role operasional:

- `superadmin`: akses penuh dan administrasi sistem.
- `ketua`: approval proposal tahap pertama.
- `bendahara`: approval/pencairan tahap akhir dan pengelolaan kas.
- `pengurus`: pengajuan proposal dan akses data sesuai scoping.

State proposal utama:

```text
pending_ketua → pending_bendahara → approved
pending_ketua → rejected
pending_bendahara → rejected
```

## 4. Protokol Kerja Wajib

### 4.1 Sebelum mengubah kode

1. Baca bagian relevan di `SYSTEM_MAP.md`.
2. Cari entrypoint dan caller aktual.
3. Telusuri flow hanya pada file yang diperlukan.
4. Periksa test yang sudah ada.
5. Periksa schema/migration jika menyentuh data.
6. Identifikasi dampak pada API, RBAC, cache, loading/error state, mobile layout, test, dan deployment.
7. Jangan melakukan blind scan seluruh repository.

Abaikan secara default:

`node_modules`, `.git`, `dist`, `build`, `coverage`, `.cache`, `.output`, file log, source map, minified asset, dan lockfile kecuali task memang terkait dependency.

### 4.2 Trace-by-flow

Gunakan urutan:

```text
User action
→ Route/View
→ Component/Composable/Store
→ Frontend Service/httpClient
→ Hono Route/Middleware
→ Service/Policy
→ Repository/Query
→ D1/R2/External API
```

Sebelum edit, tampilkan catatan ringkas:

```text
Trace: [caller] → [composable/store] → [service] → [route] → [service/repository].
Target edit: [file].
Risiko: [rendah/sedang/tinggi/kritis + alasan].
```

Perubahan auth, role, transaksi kas, approval, migration, dan lifecycle media minimal berisiko tinggi.

### 4.3 Implementasi

- Patch kecil lebih disukai daripada rewrite besar.
- Refactor boleh dilakukan jika langsung diperlukan untuk correctness, keamanan, testability, atau menghapus duplikasi dalam scope.
- Jangan menambah business logic baru ke komponen legacy.
- Jangan membuat `V3`, bridge, fallback, atau layer baru hanya untuk estetika.
- Jangan mempertahankan contract freeze lama secara otomatis. Perubahan kontrak boleh dilakukan jika diperlukan, tetapi harus end-to-end, dites, didokumentasikan, dan backward-compatible bila deployment bertahap.
- Jangan mengubah file di luar scope kecuali dibutuhkan untuk menjaga build, type safety, test, atau konsistensi kontrak.

### 4.4 Validasi

Jalankan kombinasi yang relevan:

- typecheck;
- unit test;
- integration test;
- E2E/smoke test;
- production build;
- migration test;
- RBAC/security negative test;
- responsive dan accessibility check untuk UI.

Jangan menulis `pass`, `aman`, atau `selesai` jika command/test tidak dijalankan.

## 5. Aturan Arsitektur

### Frontend

- Pertahankan dependency `View → Composable/Store → Service → API`.
- View fokus pada komposisi layar, binding event, dan state UI ringan.
- Business logic, watcher kompleks, submit orchestration, dan transformasi data berada di composable atau utility domain.
- Semua request non-trivial melalui service dan `httpClient`; hindari `fetch` langsung di view.
- Pinia digunakan untuk state global lintas fitur seperti sesi. State feature lokal tetap di composable.
- Gunakan DTO eksplisit. Hindari `any` dan type assertion yang menyembunyikan masalah.
- Gunakan formatter/parser rupiah dan tanggal yang terpusat.
- Primitive reusable berada di `src/components/ui`; komponen domain berada di folder fitur.
- Ekstrak shared component hanya ketika contract/behavior stabil dan benar-benar reusable.

### Backend

- Pertahankan dependency `Route → Schema/Policy → Service → Repository/Query → DB`.
- Route hanya parsing, validation, middleware, delegasi, dan response mapping.
- Business rule approval, void, role, serta state transition berada di service/policy.
- SQL tidak boleh berada di route.
- Repository/query tidak menentukan keputusan bisnis.
- Error client-facing harus konsisten dan tidak membocorkan stack trace, SQL, token, cookie, atau secret.

### Shared contracts

Untuk endpoint utama, prioritaskan satu source of truth untuk:

- role;
- status proposal;
- tipe transaksi;
- request/response DTO;
- filter dan pagination;
- error code;
- validation schema.

Perubahan enum harus disinkronkan ke UI, API, test, migration/reconciliation, dan dokumentasi.

## 6. Aturan Domain Kritis

### Keuangan dan proposal

- Transaksi `approved` tidak boleh di-hard-delete. Gunakan `void`, reversal, atau correction dengan actor, waktu, dan alasan.
- Semua perubahan status harus memiliki audit event.
- Approval harus atomic dengan conditional update berdasarkan status lama.
- Mutasi penting harus tahan double-submit melalui idempotency key atau guard setara.
- Reject dan void wajib memiliki alasan.
- Summary/laporan dihitung server-side berdasarkan policy.
- UI tidak boleh menentukan status final; server memaksa state berdasarkan endpoint dan role.
- Nominal harus finite, positif, dalam batas wajar, dan diparsing konsisten.
- Setelah approved, field finansial penting tidak boleh diedit langsung.
- Konflik state harus mengembalikan `409 Conflict`, lalu UI melakukan refetch dan memberi pesan yang jelas.

### RBAC

- Backend adalah otoritas. Guard UI hanya untuk UX.
- Semua policy fail-closed.
- Setiap endpoint admin harus memiliki auth dan role/data-scope eksplisit.
- `pengurus` hanya melihat data approved atau data miliknya sesuai policy.
- Cegah self-lockout, privilege escalation, dan penghapusan akun pemulihan terakhir.
- Perubahan password atau role harus merevoke sesi lama.

### Auth dan keamanan

- Secret hanya berasal dari environment/binding.
- Cookie production wajib `HttpOnly`, `Secure`, `SameSite`, dan path/scope yang tepat.
- Request mutasi berbasis cookie harus memiliki proteksi CSRF atau validasi origin yang kuat.
- Rate limit login production harus persisten lintas instance.
- Jangan mencetak password, token, cookie, secret, atau payload sensitif ke log.
- Terapkan security headers yang sesuai.

### Media D1–R2

- Storage key harus dibuat atau diverifikasi server-side dan tidak boleh menimpa object record lain.
- Metadata D1 dan object R2 diperlakukan sebagai satu lifecycle.
- Cleanup upload gagal tidak boleh menghapus object existing.
- Periksa reference usage sebelum delete.
- Gunakan archive/pending-delete untuk penghapusan aman bila media sudah dipakai konten.
- Thumbnail dan file utama harus memiliki kontrak key yang konsisten.

### Endpoint publik

- Endpoint publik read-only, output whitelist, query tervalidasi, bounded limit, dan cache policy eksplisit.
- Jangan mengekspos creator id, catatan internal, atau informasi pribadi pada transparansi kas.
- External API harus memiliki timeout, retry terbatas, cache, dan fallback.

## 7. UI/UX Standard

Tujuan: clean, profesional, user-friendly, mobile-first, accessible, dan konsisten.

Arah redesign aktif adalah full product redesign **Nurul Huda Civic Editorial**: warm modern minimalism + editorial public experience + institutional admin UI. Pertahankan identitas emerald dan accent yellow-gold yang hemat. Legacy dan V2 hanya referensi behavior, bukan referensi visual. Jangan membuat `V3` atau bridge visual baru. Gunakan primitive canonical shadcn-vue/reka; jangan menambah penggunaan Headless UI baru. Detail token, component policy, responsive contract, dan larangan visual berada di `DESIGN.md`.

- Mulai desain dari viewport 360 px.
- Satu primary action yang jelas per layar.
- Gunakan progressive disclosure untuk detail kompleks.
- Navigasi dan aksi harus role-aware.
- Gunakan design token; hindari hardcode warna, radius, spacing, dan shadow berulang.
- Hijau brand untuk identitas/active state. Accent gold/oranye digunakan hemat untuk CTA atau perhatian penting.
- Glassmorphism dan bento grid hanya digunakan jika meningkatkan hierarchy dan readability.
- Setiap layar data wajib memiliki loading, empty, recoverable error + retry, disabled/submitting, success, conflict/stale-data, dan permission state bila relevan.
- Tabel kompleks berubah menjadi card/list di mobile, bukan hanya horizontal scroll.
- Tidak ada fitur penting yang hanya tersedia melalui hover.
- Touch target sekitar 44×44 px.
- Focus ring terlihat, input memiliki label/error semantik, modal memiliki focus trap, status tidak hanya bergantung pada warna, dan animasi menghormati `prefers-reduced-motion`.

Gunakan istilah antarmuka konsisten:

- Persetujuan;
- Setujui / Tolak;
- Menunggu persetujuan ketua;
- Menunggu pencairan bendahara;
- Tambah transaksi;
- Proposal saya.

## 8. Database dan Migration

- Jangan mengubah migration lama yang mungkin sudah diterapkan di production.
- Setiap perubahan schema menggunakan migration baru.
- Gunakan pola expand → backfill → switch → contract untuk perubahan destruktif.
- Uji migration pada database fresh dan database versi sebelumnya.
- Perubahan besar memerlukan backup dan restore plan.
- Evaluasi index berdasarkan query nyata.
- Hindari N+1, unbounded list, dan fungsi pada kolom terindeks bila menghilangkan manfaat index.
- Semua default tanggal bisnis mengikuti `Asia/Jakarta`.

## 9. Testing dan Definition of Done

Minimum evidence:

- UI-only: typecheck, build, responsive check, keyboard/focus check, smoke interaction.
- API/service: unit/integration test, auth/RBAC path, error contract, build/typecheck.
- Finance: state-transition integration test, duplicate request test, summary consistency, role matrix.
- Migration: fresh apply, upgrade apply, backfill check, compatibility note.
- Media: success, partial failure cleanup, key collision, permission, referenced-delete behavior.
- Security: positive dan negative test.

Task hanya boleh dinyatakan selesai jika:

- behavior yang diminta tersedia;
- regression pada flow terkait tidak ditemukan;
- test/build relevan lulus;
- loading/error/permission state tertangani;
- dampak keamanan/data dijelaskan;
- dokumentasi diperbarui bila flow berubah;
- risiko residual dicatat jujur.

## 10. Dokumentasi

- Update `SYSTEM_MAP.md` jika route, flow utama, state machine, schema, role policy, atau ownership modul berubah.
- Update `ROADMAP.md` hanya jika prioritas, dependency, scope, atau status milestone benar-benar berubah.
- Jangan menambahkan log iterasi kosmetik panjang ke dokumen aktif.
- Histori lama dipindahkan ke `docs/archive/`.
- `RUNBOOK.md` harus diperbarui untuk perubahan deployment, migration, backup, restore, secret, atau incident response.
- Update `README.md` bila onboarding, command canonical, prerequisite, atau indeks dokumentasi aktif berubah; jangan gunakan README sebagai progress log.

## 11. Hermes-Specific Safety

- Jangan menyimpan secret, token, cookie, data pengguna, kredensial, atau detail produksi sensitif ke memory/skill Hermes.
- Jangan menjadikan progres sementara atau keputusan yang belum disetujui sebagai memory permanen.
- Skill yang dibuat harus bersifat reusable dan tidak mengandung credential atau data spesifik produksi.
- Gunakan subagent hanya untuk pekerjaan independen seperti audit, test review, atau UI review. Agent utama tetap bertanggung jawab atas integrasi dan validasi akhir.
- Hindari dua agent mengedit file yang sama secara bersamaan.
- Jangan melakukan deployment, migration remote, penghapusan data, rotasi secret, atau aksi produksi destruktif tanpa permintaan eksplisit pengguna.
