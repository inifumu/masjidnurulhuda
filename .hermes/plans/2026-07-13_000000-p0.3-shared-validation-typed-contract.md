# P0.3 Shared Validation and Typed API Contract Implementation Plan

> **For Hermes:** Implement task-by-task with strict TDD; do not commit unless the user explicitly asks.

**Goal:** Establish one shared source of truth for operational roles, finance enums/DTOs, validated filters, and machine-readable API errors, then connect validation field errors to active finance forms.

**Architecture:** Add a dependency-neutral `shared/contracts` layer importable by Vue and Hono. Keep route → validation/policy → service boundaries: shared modules define literals, DTOs, guards/parsers, response envelopes, and error codes; routes validate unknown input and map domain errors; frontend services consume shared DTOs and `httpClient` normalizes a typed error envelope. Migrate the critical finance vertical slice first instead of rewriting all 177 response call sites at once.

**Tech Stack:** TypeScript 6, Vue 3, Hono, Cloudflare D1, Node test runner, existing `vue-tsc`/Vite toolchain. No new dependency is required for the first slice; use dependency-free literal tuples and parsing functions unless audit during implementation proves Zod materially reduces duplication.

---

## Verified current context

- P0.2 is Done in the current working tree; canonical suite is 58/58 and build passes.
- The working tree is intentionally mixed and uncommitted. Touch only P0.3 files and do not stage broadly.
- Current response shape is `{ status, message, data? | errors? }`; there is no stable error `code` or typed `fields` map.
- `httpClient` parses JSON as an untyped value, uses `data?.message`, stores `ApiError.data: unknown`, and returns `data as T`.
- Operational role literals are duplicated in at least:
  - `server/middleware/auth.ts`
  - `server/services/auth.ts`
  - `server/services/user.ts`
  - `src/stores/authStore.ts`
  - `src/services/admin/pengaturanService.ts`
  - `src/utils/permissions.ts` derives another role union.
- Transaction type/status literals are duplicated between `server/services/transaction.ts`, route validation, and `src/services/admin/kasService.ts`.
- Period/filter parsing is duplicated in `server/api/admin/transaction.ts` and `server/api/admin/dashboard.ts`.
- Validation is predominantly manual and message-only. Finance forms maintain local boolean validation flags, so server field errors cannot be mapped inline.
- High-signal `any` remains in active finance UI catches/filter callbacks and legacy settings tab props. P0.3 should remove `any` in touched critical paths, not perform a repository-wide cosmetic cleanup.
- Existing tests are `.mjs` Node tests; shared contract tests should follow that convention.

## Scope decision

### Included in P0.3 closure

1. Shared roles, transaction type/status/action, category flow, period/filter DTOs.
2. Shared success/error envelope and stable error codes for critical auth/finance routes.
3. Field-error map for direct transaction and proposal validation.
4. Typed `ApiError` and safe response-envelope parsing in `httpClient`.
5. Finance frontend services importing shared DTOs rather than redefining them.
6. Active `FinanceV2` direct/proposal forms showing server field errors inline.
7. Route integration proving code/message/fields/status contracts.
8. Compile-time drift test/typecheck evidence for shared enums.

### Explicitly deferred

- Full conversion of all 177 response call sites in one release.
- Repository-wide removal of every `any`, including generated UI primitives and inactive legacy bridges.
- Pagination implementation itself; P0.3 defines reusable pagination contracts/parsers, while bounded paginated behavior remains P2.1 unless an endpoint is migrated in-scope.
- Security behavior changes from P0.4.
- Repository/module standardization from P1.2.

## Risks and mitigations

- **Breaking every API caller at once:** keep response envelope backward-compatible and migrate critical routes vertically.
- **Shared module bundling server-only dependencies into browser:** shared contracts must remain dependency-neutral and type/value only.
- **Validation/hash mismatch breaking P0.2 replay:** compute idempotency hash from normalized validated DTO plus server-owned intent, and add same-semantic-input replay tests.
- **Frontend trusts generic response body:** validate envelope shape centrally; retain caller generic only for endpoint data until runtime response schemas are adopted incrementally.
- **Scope explosion from residual `any`:** remove `any` in touched finance/auth paths; record unrelated legacy/generated residue, do not refactor it cosmetically.
- **Mixed working tree:** inspect `git diff -- <P0.3 files>` before every edit and never use broad staging/cleanup.

## Readiness decision

P0.3 is ready to start without a schema migration or external credential. Recommended first implementation slice is Tasks 1–3, followed immediately by the finance vertical slice Tasks 4–7. No blocker requires user confirmation.
