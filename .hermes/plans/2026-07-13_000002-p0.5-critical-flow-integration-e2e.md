# P0.5 Critical Flow Integration and E2E Plan

**Goal:** Membuktikan critical finance/auth/media flow secara berurutan terhadap state persistence bersama, termasuk RBAC negatif, concurrency/idempotency, period/scoping, dan migration compatibility.

**Architecture:** Gunakan Hono route aktual dengan binding D1 test yang mempertahankan state lintas request. Prioritaskan vertical critical journey daripada mock per-function; browser smoke hanya untuk behavior UI yang tidak dapat dibuktikan dari route integration.

**Constraints:** TDD, tidak menyentuh remote, tidak commit/push, tidak mengubah migration lama, dan tidak membuat harness yang menggandakan business logic production.

## Slice 1 — Shared D1 integration harness

- Buat helper test dependency-neutral untuk state users, transaksi, audit, idempotency, dan query summary.
- Harness harus mengeksekusi SQL intent production atau D1 disposable; jangan mengimplementasikan ulang policy status/RBAC.
- RED: request berurutan saat ini tidak dapat berbagi persistence lintas router.

## Slice 2 — Auth critical route flow

- Login valid mengembalikan cookie dan audit success.
- Login invalid mengembalikan `401 UNAUTHORIZED` dan audit failed tanpa data sensitif.
- Attempt keenam menghasilkan `429 RATE_LIMITED` + `Retry-After`.
- Token version mismatch dan disabled account menghasilkan `401`.

## Slice 3 — Proposal approval journey

- Pengurus submit proposal; server memaksa `pending_ketua`.
- Ketua approve menjadi `pending_bendahara`.
- Bendahara approve menjadi `approved`.
- Duplicate/replay tidak menambah row/event.
- Concurrent/stale transition hanya memilih satu hasil dan loser mendapat `409`.

Progress: journey Wrangler local D1 disposable sudah lulus untuk submit, negative approve pengurus, approve ketua, approve bendahara, approved list/summary, audit timeline, dan persistence idempotency. Residual slice: duplicate replay dan concurrent/stale terhadap harness D1 yang sama.

Temuan/fix: fresh schema menolak role bendahara karena migration 0007 no-op. Migration additive `0014` memperkenalkan `operational_role` tanpa rebuild parent users. Claim-first create juga diperbaiki agar FK `transaction_id` diisi saat finalize setelah row transaksi dibuat.

## Slice 4 — Reject, role, ownership, period, summary

- Reject dari `pending_ketua` dan `pending_bendahara` mewajibkan alasan.
- Positive/negative role matrix endpoint finance.
- Pengurus A tidak melihat pending/private milik B; approved tetap mengikuti public/admin policy.
- List admin, summary admin, dan summary publik konsisten untuk period boundary `Asia/Jakarta`.

## Slice 5 — Media and migration gates

- Pertahankan upload partial failure cleanup dan tambah key-collision/referenced-delete test sesuai behavior aktual; bila safe referenced-delete belum diimplementasikan, catat sebagai dependency P1.5, jangan rekayasa pass.
- Otomatiskan fresh `0001`–latest dan upgrade previous→latest memakai state Wrangler disposable.
- Verifikasi `PRAGMA foreign_key_check` dan schema contract.

## Stop conditions

- Jika route integration memerlukan reimplementasi SQL/policy besar di mock, pindah ke Wrangler D1 disposable atau test repository nyata.
- Jika browser smoke memerlukan credential production/remote, gunakan fixture lokal disposable; jangan menyentuh remote tanpa izin eksplisit.
- P0.5 tidak boleh Done jika full approval journey, ownership scoping, list-summary consistency, atau migration harness masih hanya unit/mocked evidence.
