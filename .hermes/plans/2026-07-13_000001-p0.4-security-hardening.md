# P0.4 Security Hardening Implementation Plan

**Goal:** Menutup risiko mutasi cookie-auth cross-origin, rate-limit login lintas isolate, lifecycle akun/revocation/recovery-admin, security headers, dan audit event keamanan dengan evidence negatif end-to-end.

**Architecture:** Pertahankan flow Hono route → middleware/policy → service/query → D1. Tambahkan middleware keamanan dependency-neutral untuk origin dan response headers; pindahkan rate-limit dari Map ke D1 dengan update atomic; tambahkan migration additive untuk status akun, rate-limit, dan security audit events; tempatkan self-lockout/last-superadmin policy di service, bukan UI atau repository.

**Constraints:** Tidak mengubah migration lama, tidak menyentuh remote, tidak commit/push, tidak membaca secret. Semua behavior baru test-first dan error memakai typed API contract P0.3.

## Baseline terverifikasi

- Cookie auth sudah `HttpOnly`, `SameSite=Lax`, `path=/`; `Secure` ditentukan dari URL request.
- Middleware exact same-origin dan security headers global sudah diimplementasikan sebagai slice pertama dan memiliki negative tests.
- Login rate limit masih `Map` memory per isolate.
- `token_version` sudah diverifikasi pada middleware dan `/auth/me`; logout membump token version.
- Role/password update belum membump token version.
- Delete/update akun belum mencegah self-lockout atau penghapusan/demotion superadmin recovery terakhir.
- Tidak ada status disabled pada users dan tidak ada security audit table.

## Slice 1 — Origin validation dan security headers

Files:
- Create `server/middleware/security.ts`
- Create `tests/security-middleware.test.mjs`
- Modify `server/index.ts`
- Modify route integration tests yang mengirim mutasi cookie-auth

Tests RED:
- mutasi admin dengan cookie tanpa Origin ditolak 403;
- Origin berbeda ditolak 403;
- same-origin diterima;
- GET tidak ditolak;
- response memiliki CSP, frame, content-type, referrer, permissions, dan HSTS hanya HTTPS.

Implementation:
- validasi exact `Origin === new URL(request.url).origin` untuk seluruh method unsafe di `/api/admin/*`, termasuk login;
- fail closed untuk Origin kosong/malformed;
- login dan logout sama-sama wajib same-origin untuk mencegah login-CSRF/session mutation cross-origin;
- middleware dipasang sebelum router.

## Slice 2 — Persistent login rate limit

Files:
- Create migration berikutnya `migrations/0013_security_hardening.sql`
- Modify `server/middleware/rateLimit.ts`
- Modify `server/api/admin/auth.ts`
- Add `tests/security-migration.test.mjs`, `tests/login-rate-limit.test.mjs`

Schema additive:
- `login_rate_limits(key_hash PRIMARY KEY, failure_count, window_started_at, blocked_until, updated_at)`;
- key disimpan sebagai SHA-256 dari normalized IP+email, bukan email/IP plaintext;
- index cleanup berdasarkan expiry.

Behavior:
- atomic consume async via D1;
- conditional UPSERT menjaga counter lintas isolate;
- `429` dan `Retry-After` stabil;
- seluruh request login yang valid secara bentuk mengonsumsi slot; login sukses tidak menghapus bucket agar tidak membuka race;
- expired bucket reset deterministik.

## Slice 3 — Account lifecycle, recovery guard, revocation, audit

Files:
- Extend migration `0013_security_hardening.sql` dengan `users.is_active` dan `security_audit_events`.
- Modify `server/services/auth.ts`, `server/db/queries/auth.ts`, `server/services/user.ts`, `server/api/admin/pengaturan.ts`.
- Modify frontend account DTO/UI only as needed.
- Add service + route tests.

Policies:
- disabled account tidak dapat login dan sesi existing ditolak;
- role change/password reset/disable membump `token_version` atomically;
- actor tidak boleh disable/delete/demote dirinya sendiri;
- superadmin aktif terakhir tidak boleh didemote, disable, atau dihapus;
- account-management dibatasi ke `superadmin`; `ketua` tidak boleh membuat/mempromosikan akun;
- account mutation menulis audit event dengan actor, target, action, timestamp, dan metadata non-sensitive;
- password/token/cookie tidak pernah masuk audit metadata/log.

## Slice 4 — Verification and documentation

- Negative route matrix untuk cross-origin, disabled/revoked session, self-lockout, last-superadmin, role/password revocation, persistent limit.
- Authenticated browser smoke same-origin tetap bekerja dan forged cross-origin ditolak.
- Fresh + upgrade local migration verification.
- Update `SYSTEM_MAP.md`, `ROADMAP.md`, `RUNBOOK.md` setelah behavior final.
- Final: `npm run test`, `npm run build`, `npm run db:apply:local`, `git diff --check`.

## Stop conditions

- Jika D1 tidak dapat memberi atomic counter semantics yang dibutuhkan melalui conditional UPSERT, hentikan slice rate-limit dan evaluasi Durable Object/KV/WAF dengan user; jangan mengklaim cross-instance konsisten.
- Jika perubahan schema memerlukan contract/destructive rebuild, gunakan migration additive baru; jangan edit migration existing.
